# 14 CSV、加密业务备份与事务恢复

## 目标

提供可携带的数据导出和经过真实演练的完整业务恢复，同时不暴露凭证与临时明文。

## 已批准的基线决策

B-02：完整业务备份只提供加密 `.pfbackup` 下载，内部载荷采用 JSON；不提供生产环境明文 JSON 完整备份下载，CSV 不承担恢复职责。

## 范围

- 交易及主要统计 CSV 导出，UTF-8 和公式注入防护。
- 用户业务备份：Scrypt + AES-256-GCM 的 `.pfbackup`，内部 manifest 与 business-data JSON；无明文 JSON 下载入口。
- 版本/结构/认证校验、恢复前自动备份、维护模式、原子恢复、完整性检查和会话清除。
- `BackupRun` 记录业务备份/恢复元数据，不记录口令或密钥。

## 不包含内容

- 运维 `pg_dump` 调度、对象存储、密码/会话迁移、原始账单导出。

## 涉及模块

`core` 编排；所有业务模块提供版本化 serializer/importer；账本规则由公开服务或受控恢复层校验。

## 主要数据模型或接口

- 设计第 38.2、39.1、42 节文件结构和流程。
- 备份格式带明确 schema/app version；每文件新盐和 nonce。

## 实施步骤

1. 定义版本化 manifest、稳定 Decimal/日期序列化和依赖顺序。
2. 实现 CSV 导出与权限/流式响应。
3. 实现内存或 tmpfs 中的加密备份，确保明文清理。
4. 实现恢复预检、恢复前备份、维护模式和 `transaction.atomic()` 导入。
5. 运行完整性检查，成功后清会话，失败整体回滚。

## 测试要求

- 逐类数据 round-trip、Decimal 精确相等、关联和停用状态保留。
- 错口令、篡改标签、未知版本、缺字段、恶意大文件、恢复中途失败。
- 恢复失败原数据逐表不变；临时明文删除；密码与会话不在备份中。
- CSV 公式注入、Unicode、换行和时区。

## 完成标准

- 完成“备份—清空测试环境—恢复—余额/记录/关联核对”自动化演练。
- 备份文件不含凭证，未登录不能导出或恢复，生产界面和接口不提供明文 JSON 完整备份。
