# 16 生产上线基线固化

## 目标

将 2026-08-03 已上线的生产配置、安全修复和验收结果固化到 Git，使本地仓库、远端主分支与生产服务器具有可追溯、可重复部署的共同基线。

## 范围

- 固化正式 HTTPS、Caddy 健康端点隔离和真实 Docker 端口绑定验证。
- 固化国内服务器离线安装 `uv` wheel 和 Python 依赖镜像源配置。
- 显式向 Web 容器传递生产 HTTPS 安全变量，不无差别注入整个 `.env`。
- 建立持续体验与需求池，并更新任务索引和生产验收记录。
- 运行完整质量门槛、推送基线提交并建立版本标签。

## 不包含内容

- 新增业务功能或修改财务统计口径。
- 修改需求/设计基线中的账务规则。
- 导入真实财务数据、执行生产数据库恢复或创建测试交易。

## 验收要求

- `ruff check .`、`pytest`、`python manage.py check` 通过。
- 生产设置 deploy check、迁移检查和 Compose 配置校验通过。
- 生产服务器四个服务健康，HTTP 跳转 HTTPS，HTTPS 与安全响应头正常。
- 公网只开放 SSH、80、443；5432 与 8000 不发布。
- 公网 `/health/*` 返回 404，内部 readiness 正常。
- 生产服务器检出已推送基线，工作区无未提交配置漂移。

## 实施记录

- 2026-08-03：公网 DNS、TLS、端口隔离、Django deploy check、账务完整性、静态资源、CSRF Cookie 和加密数据库备份已验证。
- Caddy 健康端点改为显式互斥处理，修复 `/health/*` 被反向代理公开的问题。
- 部署验证改为读取 Docker 实际宿主机端口绑定，避免新版 Compose 对未发布端口返回 `invalid IP:0` 时误报。
- 完整质量门槛通过：Ruff、252 项测试、Django check、production deploy check、迁移完整性和 Compose 配置解析均无问题。
- 生产基线版本标签：`v0.1.0`。
