# 04 手动交易主流程

## 目标

让用户通过服务端页面安全地录入和查询核心交易，形成第一版最小可用账本。

## 范围

- 收入、普通支出、信用卡消费、账户转账、信用卡还款和余额调整入口。
- 交易列表及时间、类型、账户、分类、金额、关键词筛选。
- 未锁定错误交易的编辑/作废；详情与关联展示。
- 支付渠道与实际账户分离；可选商家、备注和标签。

## 不包含内容

- 退款专用流程、账期分配、分期、模板/复制、导入、复杂前端。

## 涉及模块

`ledger`、`accounts`、`core`、共享模板。

## 主要数据模型或接口

- 调用 03 的 `ledger.services`；视图不得写 Entry。
- PRG 表单提交；HTMX 仅用于筛选和局部错误增强。

## 实施步骤

1. 为不同交易类型创建明确区分的表单和校验。
2. 实现新增、详情、列表、筛选和分页。
3. 实现仅未锁定交易可编辑；其他情况引导后续修正流程。
4. 添加防重复提交令牌或 PRG 语义，保证双击不重复记账。

## 测试要求

- 每个入口的权限、成功、校验失败和数据库回滚测试。
- 渠道与账户不混淆；信用卡还款页面仍生成 TRANSFER。
- 筛选组合、关键词转义、分页稳定性、双击/重放测试。

## 完成标准

- 浏览器可完成核心记账与筛选，且结果与 03 的 selectors 一致。
- 无 JavaScript 时主要流程仍可用。
