# 03 核心账本模型与原子服务

## 目标

实现资金事实唯一来源及可复用的原子写服务，在任何界面功能之前证明账务不变量。

## 范围

- `Transaction`、`TransactionEntry`、`Merchant`、`Tag`、`TransactionTag` 最小模型。
- 收入、支出、转账、信用卡消费、信用卡还款、退款和余额调整的底层服务。
- 账户余额、流动资产、负债和基础收支 selectors。
- 状态、锁定、作废、反向修正的领域基础设施。

## 不包含内容

- HTML 表单、账期分配、分期计划、预算、导入、报表。

## 涉及模块

`ledger`、`accounts`、`core`。

## 主要数据模型或接口

- 设计第 12～14 节全部字段、条目规则和约束。
- `ledger.services` 提供类型化命令；调用方不得直接创建 Entry。
- `ledger.selectors` 提供账户余额与按月/分类聚合。

## 实施步骤

1. 建模、索引和 DB 约束；明确金额量化到分。
2. 为每种交易实现 `transaction.atomic()` 服务和统一校验。
3. 实现有效状态过滤、余额及收支聚合 selectors。
4. 实现锁定判定、作废和反向修正基础流程。
5. 添加完整的服务层与并发/回滚测试。

## 测试要求

- 七类操作的 Entry 数量、符号和账户性质矩阵。
- 转账守恒、还款不计消费、调整不计收支、作废不影响余额。
- 退款累计上限、非法账户/分类组合、零负金额、原子回滚。
- 所有计算用 `Decimal`；覆盖 0.01、超大合法值和超精度拒绝。

## 完成标准

- 设计第 54 节中账本相关不变量由自动测试证明。
- 账户余额只由 `initial_balance + ACTIVE Entry` 计算，无缓存余额字段。
