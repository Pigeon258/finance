# 实际体验与需求池

本文持续记录系统所有者在真实使用中的体验、问题和需求，是后续版本规划的权威用户输入之一，但不直接替代具体任务文档。

## 使用方式

- 系统所有者可以直接编辑本文，也可以在对话中把临时需求告诉 Codex。
- 当系统所有者明确要求“根据需求池规划并执行”时，Codex 应先阅读本文、合并重复项、识别依赖与口径影响，再建立或更新对应任务文档。
- 临时直接提出的需求可以立即进入任务分析；如有持续跟踪价值，再保留到本文。
- 每次只实施一个任务文档定义的范围。会改变统计口径、账期归属、分期入账、备份格式或安全边界的需求，必须先完成需求或设计变更。
- 不在本文记录真实金额、密码、密钥、Cookie、完整账单行或其他敏感财务数据；示例必须脱敏。

## 状态说明

| 状态 | 含义 |
|---|---|
| 待梳理 | 已记录，尚未分析范围与优先级 |
| 待确认 | 需要系统所有者补充场景、目标或口径 |
| 已规划 | 已转换为具体任务文档 |
| 实施中 | 对应任务正在开发或验证 |
| 已完成 | 已上线并完成对应验收 |
| 暂不采用 | 当前版本不实施，并保留原因 |
